Make the distributed main-agent executor guidance require a complete failure inventory and safe, observed-Epic-head attribution before any repair choice, with deterministic evidence for the written contract.

Update existing exact-version/note assertions that would otherwise become stale. Reconcile the repository's managed installed skill through the supported sync path without silently overwriting customized copies; include lifecycle evidence for init/doctor/sync in a disposable project when practical. Do not add a second ledger or change CLI runtime behavior.
- Final validation strategy, once changes stabilize: run `pnpm verify` once for the compiled build and full deterministic suite, `node .agents/scripts/check-touched-source-file-lines.mjs` for the touched TypeScript source-size gate, and `pnpm run validate:packed-runtime` separately because the changed skill is distributed package content. The focused test below is fast feedback and does not replace the final aggregate. Inspect manifest version and sync note; use disposable lifecycle assertions where practical. Do not rerun expensive checks merely for a different permission result.
- Verification limits: unit/contract and edge/failure fixtures cover text and deterministic cases, not whether a live agent follows them. No live-model eval, behavioral QA, UI review, real PR/merge, production deployment, fuzz/property/mutation campaign, or unrelated recovery-route test is prescribed. Deeper checks are skipped because this is prompt-owned guidance with no new algorithm or runtime state; residual risk is nondeterministic agent compliance and host-specific isolation capability. If deterministic checks cannot answer an in-scope requirement, stop for an engineer-directed SDD decision rather than substituting a weaker method.
