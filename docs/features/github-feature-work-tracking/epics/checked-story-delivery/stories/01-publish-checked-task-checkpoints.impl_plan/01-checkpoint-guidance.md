# Step: Define the checked-Task publication contract

## Goal

Make prompt-owned Story execution publish each checked Task as a remote checkpoint and open one draft Story PR after the first pushed Task, without weakening existing review, check, commit, or merge gates.

## Scope

- Task ID: GFW-S03-T01; Milestone ID: GFW-S03-M01; Status: done; Depends on: none
- Story acceptance criteria: AC-01, AC-02, AC-03; source decisions: `brd.md` REQ-04, REQ-05, REQ-08, AC-03, AC-05; `sdd.md` keeps GitHub delivery prompt-owned, requires check → scoped commit → push → matching Story issue/progress → first-Task draft PR, readback before uncertain retry, and no routine later-Task prompt; on-demand pointers: `docs/features/github-feature-work-tracking/sdd.md` §§ Ownership and Boundaries, Publish a checked Task handoff (diagram and prose), State, Safety, and Operational Visibility; `docs/features/github-feature-work-tracking/ux.md` § Resume and hand off Story work; applicable skills: `.agents/skills/clean-code/SKILL.md`, `.agents/skills/structured-logging/SKILL.md`, `.agents/skills/ai-prompt-engineer-master/SKILL.md`, `.agents/skills/sibu-template-change/SKILL.md`, `.agents/skills/command-pattern/SKILL.md`
- Owning area: Sibu template guidance for the main agent and checked-Task executor. Reconcile the current late-PR rule with the first-Task draft-PR requirement; retain final Story checks and verified squash-merge gates separately. Require exact accepted plan fingerprint before Task dispatch/publication, branch/issue/PR readback and safe stop on concurrent remote advance, no false handoff from a local commit, no blind create/retry/force push, and no new CLI delivery engine.
- Keep the Story issue checklist compact; store check evidence, pushed commit, next-work context, and append-only progress in its issue artifact, not duplicate local feature files. Identify confirmed versus uncertain effects in safe operational reporting; do not expose credentials, prompts, or private artifact bodies.
- Template changes must bump `templates/manifest.json` global and affected per-template versions and replace affected `changes` notes with user-facing current-version sync notes. Preserve installer/sync local independence.
- Story-plan view: Story GFW-S03 at `docs/features/github-feature-work-tracking/epics/checked-story-delivery/stories/01-publish-checked-task-checkpoints.md`; upstream sources: `docs/features/github-feature-work-tracking/epics/checked-story-delivery/epic_brief.md`, `docs/features/github-feature-work-tracking/brd.md`, `docs/features/github-feature-work-tracking/sdd.md`, `docs/features/github-feature-work-tracking/ux.md`, `docs/architecture.md`; selected architecture `.agents/skills/command-pattern/SKILL.md`. Flags: none (Epic and Story). M01–M06 retain completed T01–T06 and their recorded checks/evidence without reinterpreting prompt-text or fake-host tests as proof of agent behavior; M08 = repair the pre-existing, exact-prose packed-validator failure (T08; installed-package file/routing and packed-runtime evidence) before M07 = incorporate the engineer-approved uncommitted brittle-test removal batch (T07; remaining executable-suite, source-size, and packed-runtime evidence). AC-01: T01, T02 guidance plus actual check/commit/remote readback at the Story gate; AC-02: T01–T03 guidance plus actual Story issue/progress and remote identity comparison; AC-03: T01–T03 guidance plus actual draft PR head/base and subsequent branch readback; AC-04: T03 guidance plus shipped-guidance comparison with binding compact/medium/wide UX at the existing Story and final Epic PR gates. T08 restores distribution-check confidence without claiming prompt behavior; T07 preserves executable local/distribution confidence for all criteria but does not itself prove prompt-owned behavior. Ordered statuses: T01 done → T02 done → T03 done → T04 done → T05 done → T06 done → T08 pending → T07 pending. The revised `sdd.md` § Quality Strategy and Planned Evidence and Story § Verification Expectations govern the final evidence; no separate QA, live-model, live-GitHub, or disposable-repository run is added.
- Durable conventions: each checked Task gets its own scoped Conventional Commit after its prescribed check and every `Done when` evidence item; main agent owns PR effects and continuation. The checked Task is not a handoff until remote branch, Story checklist/progress, and first-Task draft PR are confirmed. Later Tasks use the same PR. Preserve exact-plan independent review before Story branch/Task execution; no new routine human Task/Milestone/Story prompt and no fabricated human approval. Record execution later, not now, in story-local append-only `01-publish-checked-task-checkpoints.impl_plan/progress.log`, entries `Task ID | outcome | actual check/result | commit reference (if any) | blocker | gotchas`; review iterations also record identity/finding disposition/main-agent decision. Keep review/decision fields preparatory, not an active gate in this planning output.
